# 0002 명령어 대신 화면의 스위치

## 상황

① 장면은 "내 PC에서만 실행했는데 옆 노트북에서 열린다"를 보여 준다. 그러려면 발표 도중에 앱이 "같은 PC 전용"에서 "같은 연결의 다른 기기에도 열림"으로 바뀌어야 한다. 처음 구상은 네트워크용 실행 명령을 따로 두는 것이었다(`demo:lan`, `receiver:lan`). 발표자는 개발자가 아니고 발표 중에는 명령어를 치지 않는다.

## 결정

실행 명령은 하나씩만 둔다. 다른 기기 접속은 화면의 스위치로 켜고 끈다. 켤 때는 경고를 보여 주고 확인을 받는다. 프로그램을 다시 실행하지 않고 범위만 바뀌며, 로그인 상태·데이터·진행 단계는 그대로 유지된다.

## 버린 대안

- **네트워크용 실행 명령**: 발표 중에 프로그램을 끄고 다른 명령으로 다시 켜야 한다. 그 사이 데이터와 진행 단계가 처음으로 돌아가고, 글자 창에서 명령을 치는 모습이 청중에게 보인다. 실수로 처음부터 네트워크용으로 켜면 발표 시작 전부터 열려 있게 된다.
- **처음부터 열어 두고 화면에서만 "꺼짐"으로 표시**: 화면의 표시가 실제와 달라진다. "실행만으로 다른 기기에 열리면 안 된다"를 어긴다.
- **환경 변수나 설정 파일로 켜기**: 켜진 채 잊힐 수 있고 확인 절차를 건너뛴다.

## 결과

- 서버는 실행 중에 듣는 범위를 바꿀 수 있어야 한다. 이것이 접속 스위치라는 모듈을 낳았고, 같은 포트를 같은 PC 주소와 내부 주소로 따로 여는 방식을 요구한다.
- 스위치를 조작하는 화면(진행 화면, 받는 쪽 화면) 자체는 다른 기기에서 열리면 안 된다. 그렇지 않으면 옆 기기가 스스로 스위치를 켤 수 있다.
- 켜는 요청은 "경고에서 확인을 눌렀다"는 값을 정확히 요구한다. 화면 없이 요청만으로 켜려 해도 그 값이 있어야 한다.
- 실행 인자·환경 변수로 스위치를 켜는 길을 나중에 더할 수 없다.
- 받는 쪽 프로그램도 같은 스위치를 자기 화면에 가진다. 두 대로 진행하면 발표자가 스위치 둘을 따로 켜고 따로 연장해야 한다.
