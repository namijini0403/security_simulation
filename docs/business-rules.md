# 동작 규칙

## 낱말

| 낱말 | 뜻 |
|---|---|
| 1번 앱 / 2번 앱 | 같은 화면과 같은 요청 경로를 가진 성적 관리 앱 두 개. 화면에 나오는 이름은 이 중립적인 이름뿐이다 |
| 권한 확인 | 서버가 "이 사람이 이 요청을 해도 되는가"(역할과 담당 학생)를 확인하는 것. **로그인했는지만 보는 것은 권한 확인이 아니다** |
| 옆 사람 화면 | 로그인 없이 열리는, 주소만 아는 사람이 할 수 있는 요청을 단추로 옮긴 화면(`/neighbor`) |
| 받는 쪽 | 가상의 온라인 표와 가상의 AI 서비스 역할을 하는 별도 프로그램 |
| 다른 기기 접속 스위치 | 같은 PC 전용 ↔ 같은 연결의 다른 기기에도 열림을 오가는 스위치. 시연 프로그램과 받는 쪽 프로그램이 각자 하나씩 가진다 |
| 같은 PC / 다른 기기 | 접속 기록에서 요청을 보낸 주소가 이 PC 자신(127.x, ::1, 이 PC의 내부 주소)인지 아닌지. 표시용이다 |
| 가져간 것 | 옆 사람 화면이 실제로 받아 간 학생 기록 |
| 공개 | 두 앱에 같은 요청 다섯 개를 실제로 보내 결과를 나란히 보여 주는 장면. 이때 처음으로 어느 앱이 어떤 앱인지 드러난다 |

## 학생 기록

- 가상의 6학년 한 반, 정확히 20명. 번호 `TEST-1001`~`TEST-1020`이 유일한 식별자다.
- 한 기록은 번호, 이름(`가상학생NN`), 반(`6학년 가상반`), 과목 5개(국어·수학·사회·과학·영어) 각각의 평가(잘함·보통·노력요함), 담임 종합의견, 보호자 이름(`가상보호자NN`), 보호자 연락처(`010-XXXX-00NN`, 글자 `XXXX` 그대로)로 이루어진다. 번호의 NN과 이름·보호자·연락처의 NN은 항상 같다.
- 초기값은 무작위가 아니다. 실행할 때마다, 초기화할 때마다 같은 값이다. `TEST-1001`의 초기 평가에는 `노력요함`이 적어도 하나 있어야 한다('내 아이 성적 고치기'가 눈에 보이는 변화를 만들어야 하므로).
- 바뀔 수 있는 것은 평가뿐이다. 번호·이름·반·의견·보호자 정보를 바꾸는 요청은 없다.
- 두 앱은 각자 사본을 가진다. 한 앱에서 고치거나 지워도 다른 앱의 사본은 그대로다.
- 지운 학생은 그 앱에서 사라지고, 그 번호를 가리키는 요청은 404가 된다. 이미 지운 학생을 다시 지워도 404다. 되살리는 방법은 전체 초기화와 프로그램 다시 실행뿐이다.

### 성적 저장

- 과목 일부만 보내도 된다. 보낸 과목만 바뀐다.
- 5개 과목이 아닌 이름이 하나라도 있거나, 값이 세 평가 중 하나가 아니거나, 과목이 하나도 없으면 400이고 **아무 과목도 바뀌지 않는다**(일부만 반영되는 일이 없다).
- 본문의 다른 항목(이름, 의견, 번호, 역할, 주소 등)은 읽지 않는다. 있어도 무시하고 평가만 반영한다.
- 동시에 같은 값을 고치는 경우를 따로 다루지 않는다. 나중에 온 요청이 이긴다.

## 계정과 로그인 상태

- 계정은 고정이다. 학부모 20개(`parent01`~`parent20`, 비밀번호 `demo1234`)와 담임 1개(`teacher` / `teacher1234`). 가입·비밀번호 변경·계정 삭제는 없다.
- `parentNN`은 정확히 `TEST-10NN` 한 명과 묶여 있다. 담임은 담당 학생이 없다(`null`).
- 로그인 상태는 "이 브라우저는 누구인가"를 서버가 기억한 것이고, 앱마다 별개다. 한 앱의 로그인은 다른 앱에서 로그인 안 한 것으로 다뤄진다.
- 같은 브라우저가 로그인된 채 다시 로그인하면 이전 로그인 상태는 끝나고 새 것으로 바뀐다.
- 로그인 상태가 끝나는 경우: 로그아웃, 같은 브라우저의 재로그인, 전체 초기화, 프로그램 종료. 시간이 지나서 끝나지는 않는다.
- 전체 초기화로 무효가 된 브라우저의 요청은 로그인 안 한 것으로 다룬다.

## 두 앱의 차이

두 앱은 화면, 문구, 경로, 응답 형식, 다른 곳으로 보내는 동작이 완전히 같다. 다른 것은 권한 확인 여부 하나다.

- **1번 앱**은 권한을 확인하지 않는다. 한 학생의 기록 조회만 로그인을 요구하고(로그인만 했으면 누구의 기록이든 준다), 명단·반 전체 기록·성적 저장·AI 초안·삭제는 로그인 없이도 된다.
- **2번 앱**은 요청마다 로그인 상태의 역할과 담당 학생을 확인한다. 학부모는 자기 아이 한 명의 조회만 되고, 나머지는 담임만 된다.
- 거절이 먼저다. 401이나 403을 받을 사람에게는 번호가 없는 학생이거나 본문이 잘못되었더라도 401/403이 나간다(두 앱 모두). 예: 1번 앱에서 로그인 없이 없는 번호를 조회하면 404가 아니라 401이다.
- 두 앱의 첫 화면은 똑같이 로그인 화면이다. 1번 앱에서 로그인 없이 명단이 열리는 것은 명단 주소를 직접 불렀을 때뿐이고, 첫 화면에 명단을 띄우지 않는다.
- 학부모로 로그인하면 '내 아이 성적표'만 보이고 담임 메뉴는 보이지 않는다(두 앱 모두). 메뉴가 보이지 않는 것과 요청이 막히는 것은 별개다.

## 다른 곳으로 보내기

두 앱이 똑같이 한다. 보내는 것은 브라우저가 아니라 앱 서버다.

| 계기 | 보내는 내용 | 앱의 응답 |
|---|---|---|
| 성적 저장이 성공했다 | 그 학생의 전체 기록(7개 항목) → 받는 쪽의 온라인 표 | 전송을 기다리지 않고 바뀐 기록을 200으로 돌려준다 |
| AI 종합의견 초안을 요청했다 | 번호·이름·평가·의견 네 항목 → 받는 쪽의 AI 서비스 | 받는 쪽이 돌려준 초안 문장을 그대로 `{draft}`로 돌려준다 |
| 학생 기록을 지웠다 | **아무것도 보내지 않는다** | 200 |

- 앱 화면은 다른 곳으로 보낸다는 사실을 알리지 않는다. 성적 저장 뒤에는 "저장되었습니다"만 나온다. 조용히 나간다는 것이 이 장면의 요점이다.
- 받는 쪽에 닿지 못해도 성적 저장은 성공(200)이고 기록은 실제로 바뀐다. 실패는 전송 기록에만 남아 진행 화면에 나온다. 성적 저장을 실패로 만들면 안 된다.
- AI 초안은 받는 쪽에 닿지 못하거나, 받는 쪽이 거절하거나, 초안 문장 없이 대답하면 502와 한국어 설명을 돌려준다.
- 목적지는 진행 화면에서 정한 받는 쪽 주소 하나다. 요청의 주소·본문·머리글로는 바꿀 수 없다.
- 2번 앱에 동의 화면이나 이름 가리기 같은 "덜 보내는" 장치를 넣지 않는다. 전송 장면에서 두 앱이 다르면 "이렇게 하면 보내도 괜찮다"는 오해를 만든다.
- 한 번 받는 쪽에 도착한 것은 앱에서 되돌릴 수 없다. 앱에서 원본을 지워도 받는 쪽은 알지 못한다.
- 전체 초기화 전에 시작해 아직 끝나지 않은 전송의 결과는 초기화 뒤의 전송 기록에 넣지 않는다.

## 받는 쪽

- 받은 것은 온라인 표와 AI 서비스 두 목록에 받은 순서대로 쌓인다. 같은 학생이 다시 와도 덮어쓰지 않고 줄을 더한다. 항목마다 받은 시각, 보낸 쪽 주소, 받은 본문 그대로를 가진다.
- 가상 데이터 모양이 아닌 것은 받지 않는다(400, 저장하지 않음). 조건은 모두 만족해야 한다.
  - 항목 이름이 정해진 것과 정확히 같다. 온라인 표는 7개, AI 서비스는 번호·이름·평가·의견 4개. 빠져도, 더 있어도 거절한다.
  - 번호가 `TEST-1001`~`TEST-1020`이다.
  - 이름·반·보호자 이름·연락처가 그 번호의 가상 값과 글자까지 같다(`TEST-1003`이면 `가상학생03`, `가상보호자03`, `010-XXXX-0003`).
  - 평가가 정확히 5개 과목이고 값이 세 평가 중 하나다.
  - 의견이 그 번호의 가상 기록에 들어 있는 문장과 글자까지 같다. 다른 글은 길이나 내용과 상관없이 받지 않는다(다른 번호의 가상 문장도 받지 않는다).
  - 본문이 16KB 이하다.
- 따라서 받는 쪽에 저장되는 기록이 코드가 만든 가상 기록과 다를 수 있는 곳은 다섯 과목의 평가뿐이고, 그 값도 세 평가 중 하나다. 사람이 쓴 글이 저장될 자리가 없다.
- 표와 AI 서비스는 각각 2,000개까지만 담는다. 가득 차면 507로 거절하고 받는 쪽 화면에서 지우라고 알린다.
- AI 초안은 미리 써 둔 문장이다. 받은 평가에서 `잘함`인 과목과 `노력요함`인 과목의 이름만 끼워 넣는다. 받은 이름·의견은 초안에 쓰지 않는다. 초안에는 "[사전 작성된 모의 응답]"과 실제 AI가 쓴 글이 아니라는 문장이 들어간다.
- 받은 내용이 비워지는 경우: 받는 쪽 화면의 '받은 내용 모두 지우기', 지우기 요청(전체 초기화가 보낸다), 받는 쪽 프로그램 종료. 그 밖에는 남는다.

## 다른 기기 접속 스위치

시연 프로그램(진행 화면에서 조작)과 받는 쪽 프로그램(받는 쪽 화면에서 조작)이 같은 규칙을 따르되 서로 독립이다. 하나를 켜거나 끄거나 연장해도 다른 하나는 그대로다.

| 지금 상태 | 일어난 일 | 결과 |
|---|---|---|
| 꺼짐 | 켜기 + 경고에서 확인을 눌렀다는 값 | 켜짐, 남은 시간 30분 |
| 꺼짐 | 켜기(확인 값 없음, 또는 값이 정확히 참이 아님) | 꺼짐 그대로, 거절 |
| 꺼짐 | 연장 | 꺼짐 그대로, 거절 |
| 꺼짐 | 끄기 | 꺼짐 그대로(오류 아님) |
| 켜짐 | 켜기 + 확인 값 | 켜짐 그대로. **남은 시간은 늘지 않는다**(늘리는 것은 연장뿐) |
| 켜짐 | 연장 | 그 순간부터 다시 30분 |
| 켜짐 | 끄기 | 꺼짐. 다른 기기의 새 접속이 즉시 불가능해지고 열려 있던 연결도 끊긴다 |
| 켜짐 | 30분이 지남 | 꺼짐 + "다른 기기 접속이 자동으로 꺼졌습니다" 알림(알림을 닫거나 다시 켜면 사라진다) |
| 켜짐 | 프로그램 종료 | 열려 있던 접속도 끝난다 |

- 실행 직후에는 꺼져 있다. 꺼져 있는 동안 다른 기기에서는 거절 응답이 아니라 **연결 자체가 되지 않는다**.
- 켜고 끄는 동안 프로그램은 다시 실행되지 않고, 로그인 상태·데이터·진행 단계가 그대로 유지된다.
- 켜져 있어도 같은 PC와 사설 주소(10.x, 172.16~31.x, 192.168.x, 169.254.x)에서 온 요청만 처리한다. 그 밖의 주소에서 온 요청은 403이다.
- 남은 시간이 2분 이하이면 눈에 띄게 알린다.
- 켜져 있는 동안 이 PC의 내부 주소를 5초마다 다시 살핀다. 와이파이를 바꿔 주소가 달라지면 새 주소로 열고 사라진 주소는 닫는다.
- 내부 주소가 여러 개면 모두 보여 주고 모두에 연다(연결이 없을 때 자동으로 붙는 169.254.x는 맨 뒤에 둔다). 하나도 없으면 스위치는 켜지지만 열린 주소가 없고, 찾지 못했다는 안내와 직접 확인하는 방법을 보여 준다.
- '두 번째 노트북에 입력할 주소'는 켜져 있고 실제로 열린 주소에 대해서만 나온다.
- 진행 화면은 스위치의 대상이 아니다. 전체 초기화도 스위치를 건드리지 않는다(켜져 있으면 켜진 채 남은 시간이 계속 줄어든다).

## 접속 기록과 가져간 것

- 접속 기록은 두 앱이 처리한 모든 요청을 한 줄씩 남긴다. 화면 파일을 여는 요청과 없는 주소에 대한 404도 한 줄이다. 진행 화면과 받는 쪽으로 온 요청은 대상이 아니다.
- 스위치가 앱에 넘기기 전에 막은 것(꺼져 있을 때의 접속 시도, 사설 주소가 아닌 곳의 요청)은 기록에 남지 않는다.
- 한 줄에는 시각, 어느 앱, 보낸 주소, 같은 PC인지 다른 기기인지, 로그인한 사람, 요청 방식과 경로, 결과 번호가 들어간다. 로그인에 성공한 줄에는 방금 로그인한 사람이, 로그아웃 줄에는 로그아웃한 사람이 적힌다.
- 같은 PC의 브라우저가 이 PC의 내부 주소로 접속한 요청은 '같은 PC'로 표시된다. '다른 기기'와 "다른 기기에서 접근 요청 수신"은 실제로 다른 기기에서 왔을 때만 나온다.
- 기록은 앱마다 가장 최근 2,000줄까지 남는다.

'옆 기기가 가져간 것'을 세는 규칙:

- 옆 사람 화면 표시(`X-Demo-Screen: neighbor`)가 붙은 요청만 센다. 같은 PC든 다른 기기든 같다. 담임·학부모 화면의 요청과 공개 장면의 요청은 세지 않는다.
- 한 학생 조회 또는 반 전체 조회가 200으로 돌려준 학생만 센다. 성적 고치기의 응답으로 나간 기록은 세지 않는다.
- 인원 수는 서로 다른 학생 수다. 같은 학생을 여러 번 가져가도 1명이고, 보여 주는 내용은 가장 최근에 가져간 것이다.
- 1번 앱과 2번 앱을 따로 센다.
- 명단(번호와 이름만)은 "명단 열람: N명"으로 따로 보여 주고 인원 수에 넣지 않는다.
- 인원 수는 접속 기록의 오래된 줄이 밀려나도 줄지 않는다. 전체 초기화로만 0이 된다.
- 표시는 화면 표시용일 뿐이다. 붙이든 떼든 권한에는 아무 영향이 없다.

'받는 쪽에 도착한 것'은 진행 화면 서버가 받는 쪽에 실제로 물어본 결과다. 받는 쪽에 제대로 물어보지 못한 동안(아직 묻는 중이거나, 닿지 못했거나, 대답을 읽지 못했을 때)에는 예전에 받아 둔 목록을 보여 주지 않는다. 그렇다고 0건이라고 하지도 않는다. 받는 쪽에는 여전히 받은 것이 남아 있을 수 있으므로 개수 자리에 "확인하지 못함"이라고 적고, 닿지 못했으면 "받는 쪽에 닿지 못했습니다"를 함께 보여 준다. "N건"과 "아직 도착한 것이 없습니다."는 받는 쪽이 실제로 그렇게 대답했을 때만 나온다. 받는 쪽 주소가 이 PC 자신이면 "같은 PC 안의 별도 프로그램", 아니면 "다른 기기"라고 표시한다(닿지 못해도 이 표시는 주소로 정한다).

## 옆 사람 화면

단추 일곱 개는 모두 그 앱 자신에게 실제 요청을 보낸다. 다른 앱이나 다른 곳으로는 보내지 않는다.

1. 명단 주소 직접 열기 — 반 명단 요청(로그인 여부와 무관하게 그대로 보낸다)
2. 학부모로 로그인 — `parent01`
3. 내 아이 성적표 조회 — `TEST-1001`
4. 학생번호만 바꿔 조회 — `TEST-1002`~`TEST-1020` 중 고른 번호
5. 반 전체 수집 — `TEST-1001`부터 `TEST-1020`까지 한 명씩 차례로, 요청 사이 약 0.15초
6. 숨겨진 담임 기능 부르기 — 반 전체 기록 요청
7. 내 아이 성적 고치기 — `TEST-1001`의 5개 과목을 모두 `잘함`으로

- 요청마다 요청 주소, 요청한 사람, 대상 학생 번호, 결과 번호, 받은 내용을 보여 준다.
- 반 전체 수집에서 200으로 받은 학생은 '받아낸 인원'으로, 그 밖의 결과(거절, 지워진 번호의 404)는 모두 받아내지 못한 것으로 센다. 도중에 404가 나와도 멈추지 않고 20번까지 간다.
- 이 화면은 권한을 얻게 해 주지 않는다. 결과는 그 앱의 서버가 정한다. 같은 단추를 2번 앱에서 누르면 2번 앱의 규칙대로 거절된다.

## 진행 단계

- 단계는 여덟 개이고 순서는 시작 → ① → ② → ③ → ④ → 공개 → 2부 → 마무리다.
- '다음'·'이전'으로 한 칸씩, 또는 단계 단추로 어느 단계든 바로 옮길 수 있다. 첫 단계에서 '이전', 마지막 단계에서 '다음'은 거절된다.
- 단계 이동은 다른 상태를 바꾸지 않는다. 학생 기록, 로그인 상태, 스위치, 공개 여부, 2부의 진행은 그대로다.
- ① 단계에서 스위치가 꺼져 있는 동안에는 "지금은 이 PC에서만 열립니다"가 단계 화면에 함께 나온다.
- 마무리의 일곱 문장은 마무리 단계에 있을 때만 화면으로 나가고, 여섯 번째 문장("개발은 자유롭게, 개인정보 처리는 신중하게.")만 강조한다.

## 공개

- 공개 여부는 단계와 별개의 상태다. '공개' 단추로만 켜지고 전체 초기화(또는 다시 실행)로만 꺼진다. 공개 단계로 옮겨 가는 것만으로는 켜지지 않고, 다른 단계로 옮겨도 꺼지지 않는다.
- 공개 전에는 진행 화면 어디에도 어느 앱이 권한을 확인하는 앱인지, 요청마다 권한을 확인했는지가 나오지 않는다.
- '공개'를 누르면 두 앱 각각에 아래 다섯 요청을 실제로 보내고, 돌아온 결과 번호와 내용을 나란히 보여 준다.

| 시도 | 1번 앱에서 기대되는 결과 | 2번 앱에서 기대되는 결과 |
|---|---|---|
| 로그인 없이 명단 주소 열기 | 200 | 401 |
| `parent01`로 자기 아이(`TEST-1001`) 조회 | 200 | 200 |
| `parent01`로 `TEST-1002` 조회 | 200 | 403 |
| `parent01`로 반 전체 기록 받기 | 200 | 403 |
| `parent01`로 자기 아이 성적 고치기(5개 과목 모두 `잘함`) | 200 | 403 |

- 표의 숫자는 기대값일 뿐이다. 화면에는 실제로 돌아온 값을 쓴다. 앞 단계에서 `TEST-1001`이나 `TEST-1002`를 지웠다면 404가 그대로 나온다. 그래서 ④ 장면에서는 이 두 학생이 아닌 학생을 지우게 안내한다.
- 대답을 받지 못한 시도는 결과 번호 없이 "대답을 받지 못했습니다"로 나온다. 기대값으로 채우지 않는다.
- 다섯 번째 시도는 진짜 요청이다. 1번 앱에서는 `TEST-1001`의 성적이 실제로 바뀌고 그 기록이 받는 쪽으로도 나간다. 감추지 않고 화면에 그렇게 적는다. '공개'를 누를 때마다 받는 쪽에 한 줄씩 늘어난다.
- 다시 누르면 다섯 요청을 다시 보내고 결과를 바꿔 쓴다. 로그인은 누를 때마다 새로 하고 끝나면 로그아웃한다. 이미 보내는 중일 때 또 누르면 거절된다.
- 공개 요청은 접속 기록에는 남지만 옆 사람 화면 표시가 없으므로 '가져간 것'에는 세지 않는다.
- 공개 요청을 보내는 도중에 전체 초기화를 하면, 초기화는 보내는 중인 공개 요청이 모두 끝나기를 기다린 다음에 진행된다(공개 요청 전체에 걸린 시간 제한이 있어 기다림은 끝이 있다). 그래서 초기화가 끝난 뒤에 공개 요청이 도착해 성적을 바꾸거나 받는 쪽으로 나가는 일이 없다. 그 공개의 결과는 버려지고 공개 전 상태로 남는다.
- 전체 초기화가 진행되는 동안에는 '공개'를 새로 시작할 수 없다(거절된다).
- 공개 뒤에는 접속 기록의 모든 줄(공개 전에 쌓인 줄 포함)에 '권한 확인함 / 권한 확인 안 함'이 함께 나온다. 이 값은 앱이 그 요청을 처리할 때 남긴 값이다. 1번 앱은 모든 요청이 '확인 안 함', 2번 앱은 로그인·로그아웃을 뺀 모든 요청이 '확인함'이다.
- 공개 뒤에 함께 나오는 설명: 두 앱의 차이는 권한 확인 하나뿐이라는 것, 2번 앱도 다른 기기에서 열리기는 한다는 것(로그인에서 막힐 뿐), 다른 곳으로 보내는 것은 두 앱이 똑같다는 것, 2번 앱은 접근통제 원리 하나를 보여 주는 비교용 예제이지 실제 학교 서비스에 그대로 쓸 수 있는 인증 체계가 아니라는 것. 마지막 안내는 앱 화면에는 넣지 않는다(구분되면 안 되므로).

## 2부

진행 화면 안의 단계다. 대상은 가상학생07 한 명의 5일치 감정일지다. 발표자가 선생님들의 손이나 대답을 받아 대표로 누른다. 데이터는 어디로도 나가지 않는다.

순서는 여덟 칸이고 건너뛸 수 없다.

| 칸 | 내용 | 다음으로 가는 조건 |
|---|---|---|
| 1 감정일지 | 5일치 일지 | 없음 |
| 2 관찰된 사실 | 일지에서 실제로 확인되는 것만 | 없음 |
| 3 AI의 해석 | 미리 써 둔 가짜 해석 + "사전 작성된 모의 응답입니다. 실제 AI를 호출하지 않았습니다" | 없음 |
| 4 첫 선택 | 세 선택지 중 하나 | 첫 선택을 해야 한다. 고른 뒤 '다음'은 첫 번째 맥락을 여는 것과 같다 |
| 5 추가 맥락 | 누를 때마다 하나씩, 모두 네 개 | '다음'으로는 넘어갈 수 없다. 네 번째를 열면 자동으로 6으로 간다 |
| 6 다시 선택 | 같은 세 선택지 | 다시 선택을 해야 한다 |
| 7 나란히 보기 | 두 선택을 나란히 | 없음 |
| 8 설명과 문구 | 앵커링, 자동화 편향, 교사의 역할, 세 문구 | 마지막 칸이다 |

- 첫 선택을 하기 전에는 추가 맥락을 열 수 없다.
- 첫 선택은 첫 번째 맥락을 열기 전까지만 바꿀 수 있다. 맥락을 하나라도 열면 고정된다.
- 네 개를 모두 열기 전에는 다시 선택할 수 없다. 다시 한 선택은 나란히 보기로 넘어가기 전까지만 바꿀 수 있다.
- 아직 열지 않은 칸의 내용(사실, 해석, 선택지, 맥락, 설명)은 화면으로 나가지 않는다. 일지만 처음부터 보인다.
- 맥락은 월·화·수·금 네 개다. 목요일의 "그냥 그래요."에는 맥락이 없고, 네 개를 다 연 뒤에 그 사실을 따로 알린다.
- 두 선택이 같으면 "선택이 유지되었습니다", 다르면 "선택이 바뀌었습니다"만 표시한다. 어느 선택이 정답이라고 표시하지 않는다.
- 화면에 보이는 선택은 발표자가 실제로 누른 것이다. 미리 정해 둔 선택을 보여 주지 않는다.
- '2부만 처음으로'는 2부만 첫 칸으로 되돌린다. 다른 상태는 그대로다. 전체 초기화도 2부를 첫 칸으로 되돌린다.
- 순서를 어긴 요청은 거절되고 이유가 한국어로 나온다.

내용의 선:

- 병명, 질환 분류, 점수, 위험 등급, 진단을 넣지 않는다. 가짜 AI 해석은 "정서적 위축과 가정 내 스트레스가 의심됩니다. 보호자 면담과 전문 상담 연계를 권고합니다." 수준에서 멈춘다.
- 일지·해석·맥락 문장은 뜻을 유지하는 범위에서 다듬을 수 있다. 더 심각하게 만들거나 사례를 더하지 않는다.
- 특정 학교, 교사, 교육청, 우수사례를 떠올리게 하는 이름이나 표현을 쓰지 않는다.
- 외부 AI에 대한 경고는 문구로만 한다("학생의 개인정보·민감정보를 외부 AI 서비스에 보내면 안 됩니다."). 2부에서 실제로 무언가를 보내 보이지 않는다.

## 전체 초기화

단추 하나로 다음이 한꺼번에 일어난다.

- 두 앱의 학생 기록 20명이 초기값으로 돌아온다.
- 두 앱의 모든 로그인 상태가 무효가 된다.
- 접속 기록, 전송 기록, 가져간 것이 비워진다.
- 진행 단계가 '시작'으로, 2부가 첫 칸으로 돌아가고 공개 상태가 풀린다.
- 아직 가는 중인 전송이 받는 쪽에 도착하기를 기다린 다음(최대 약 3.5초) 받는 쪽에 지우기 요청을 보낸다. 순서가 반대면 뒤늦게 도착한 줄이 초기화 뒤에 남는다.

건드리지 않는 것: 받는 쪽 주소, 스위치 상태와 남은 시간.

- 받는 쪽을 지우지 못하면 "받는 쪽은 지우지 못했습니다. 받는 쪽 화면에서 직접 지우세요"를 알린다. 나머지 초기화는 그대로 이루어진다. 지우지 못한 이유는 실제로 일어난 일에 따라 둘로 나누어 함께 알린다.
  - 받는 쪽이 지우기 요청에 대답하지 않았다: '받는 쪽에 도착한 것'은 닿지 못함으로 표시하고 개수는 "확인하지 못함"이다.
  - 받는 쪽이 대답은 했지만 지우지 않았다(200이 아닌 대답): 닿지 못했다고 하지 않는다. 실제로 받은 결과 번호를 함께 알리고, '받는 쪽에 도착한 것'은 받는 쪽에 곧바로 다시 물어본 결과를 보여 준다.
- 초기화하는 중에 또 누르면 거절된다.
- 초기화 뒤에 이미 열려 있던 앱 화면은 다시 로그인해야 한다. 1번 앱의 담임 화면은 명단이 계속 보여서(명단은 누구에게나 준다) 로그인된 것처럼 보이지만 학생을 열면 "로그인이 필요합니다."가 나온다.

프로그램을 다시 실행하면 전체 초기화에 더해 받는 쪽 주소가 `127.0.0.1`로, 스위치가 꺼짐으로 돌아간다.

## 받는 쪽 주소

- 진행 화면의 입력 칸 하나다. 처음 값은 `127.0.0.1`이다.
- 받아들이는 것은 같은 PC 주소(127.x.x.x)와 사설 IPv4(10.x, 172.16~31.x, 192.168.x, 169.254.x)를 숫자 네 마디로 적은 것뿐이다. 앞뒤 빈칸은 떼고 본다.
- 거절하는 것과 이유: 빈 값, 이름(`localhost` 포함), 공인 주소, 포트·`http://`·경로가 붙은 것, IPv6, 0으로 시작하는 마디나 16진수 같은 다른 표기. 거절하면 값은 바뀌지 않고 이유를 한국어로 알린다.
- 포트는 받는 쪽 포트로 고정이다. 이 칸으로 바꿀 수 없다.
- 주소를 바꾸면 예전 주소에서 받아 둔 '도착한 것'과 연결 확인 결과는 버린다.
- '연결 확인'은 받는 쪽에 실제로 물어본다. 200이 왔더라도 받는 쪽 프로그램의 대답 모양이 아니면 연결된 것으로 치지 않는다. 실패하면 원인 후보 다섯 가지(받는 쪽 프로그램이 꺼져 있음, 받는 쪽 스위치가 꺼져 있음, 방화벽, 두 노트북이 같은 연결이 아님, 기기 간 통신을 막는 와이파이)와 조치를 함께 보여 준다.

## 시작할 때의 경계 상황

- 포트가 이미 쓰이고 있으면 어떤 포트가 막혔는지와 할 일(먼저 실행한 창을 닫기)을 한국어로 알리고 끝난다. 시연 프로그램은 셋 중 하나라도 열지 못하면 이미 연 것을 모두 닫는다. 일부만 뜬 채로 계속 돌지 않는다.
- Node.js가 22보다 낮으면 한국어로 알리고 끝난다.
- 받는 쪽이 꺼져 있는 채로 시연 프로그램을 시작해도 된다. 받는 쪽은 나중에 켜도 다시 실행할 필요 없이 이어진다.

## 화면 글의 규칙

- 사용자에게 보이는 글과 오류 안내는 모두 한국어이고 개발 용어를 피한다. "요청 주소", "결과 번호" 정도까지만 쓴다. 결과 번호(200/401/403/404)는 그대로 보여 준다 — 실제 응답임을 보이기 위해서다.
- 모든 화면 상단에 항상 `교육용 실습 / 100% 합성 데이터 / 실제 개인정보 입력 금지`를 둔다. 로그인 화면에는 교육용 계정이며 실제 인증 체계를 대신하지 않는다는 문장을, 받는 쪽 화면에는 실제 서비스가 아니라 흉내 낸 프로그램이라는 문장을 둔다.
- 단정하지 않는다. 같은 연결에 있다고 항상 접속되는 것은 아니고(방화벽, 기기 간 차단), 실제 서비스에 데이터가 반드시 남는다고도 말하지 않는다. ④ 장면의 원리는 "다른 시스템에 복제된 데이터는 삭제 범위를 따로 관리해야 한다"이다.
- 실제 업무·학교·사례를 떠올리게 하는 요소를 넣지 않는다.
