# src/shared — 공통 기반

## 맡는 것

- `data.js` — 가상 학생 20명과 고정 계정 21개를 만든다. 학생 번호 형식 확인.
- `address.js` — 주소 판별(같은 PC·사설 주소인가), 받는 쪽 주소 확인과 조립, 이 PC의 내부 주소 찾기.
- `access-switch.js` — 다른 기기 접속 스위치. 서버를 등록받아 `127.0.0.1`에 열고, 켜지면 내부 주소마다 문을 더 연다.
- `http.js` — JSON 본문 읽기, 응답 보내기, 화면 파일 내보내기, 쿠키, 기본 브라우저 열기, 같은 PC 전용으로 서버 열기, 시작 실패 안내, Node.js 버전 확인.
- `config.js` — 기본 포트와 환경 변수 읽기.

## 맡지 않는 것

- 누가 무엇을 할 수 있는가(권한 판단)는 여기에 없다. `src/app/`의 일이다.
- 화면에 나오는 단계·2부·공개 문구는 여기에 없다. `src/console/content.js`의 일이다. 여기에 있는 문구는 스위치의 안내문과 시작 실패 안내문뿐이다.
- `src/app/`, `src/console/`, `src/receiver/`, `src/demo.js`를 가져오지 않는다. 이 폴더는 Node.js 내장 모듈만 가져온다.
- 이 폴더의 파일은 불러오는 것만으로 아무 일도 하지 않는다. 포트를 열거나 프로그램을 끝내는 것은 부르는 쪽이 함수를 불렀을 때뿐이다.

## 항상 성립해야 하는 것

**가상 데이터**
- `createStudents()`는 부를 때마다 같은 값의 새 객체 20개를 돌려준다. 무작위 값, 시각, 환경에 따라 달라지는 값을 쓰지 않는다.
- 번호 `TEST-10NN`, 이름 `가상학생NN`, 보호자 `가상보호자NN`, 연락처 `010-XXXX-00NN`의 NN이 한 기록 안에서 같다. 받는 쪽이 이 대응을 글자 그대로 확인하므로, 형식을 바꾸면 받는 쪽이 모든 전송을 거절한다.
- `TEST-1001`의 초기 평가에 `노력요함`이 적어도 하나 있다.
- 실제 이름·연락처처럼 보이는 값을 만들지 않는다.

**주소**
- `parseIPv4`는 십진수 네 마디만 받는다. 0으로 시작하는 마디, 16진수, 빈칸, 포트가 붙은 것은 `null`이다. 느슨하게 만들지 않는다.
- `isPrivateOrLoopback`이 참인 것은 127.x, `::1`, 10.x, 172.16~31.x, 192.168.x, 169.254.x와 그것을 담은 `::ffff:` 표기뿐이다. 글자가 아닌 값과 그 밖의 모든 것은 거짓이다.
- `validateReceiverHost`는 이름을 받지 않는다(`localhost` 포함). 이름 풀이를 거치는 길을 만들지 않는다.
- `receiverBaseUrl`은 확인을 통과하지 못하면 예외를 던진다. 실패했을 때 기본값으로 대신하지 않는다.
- `isSamePcAddress`는 표시용이다. 허용 판단에 쓰지 않는다.

**접속 스위치**
- 만들어진 직후에는 꺼져 있다. `turnOn`은 인자가 정확히 `{ confirmed: true }`일 때만 켠다.
- 꺼져 있는 동안 내부 주소에서 듣는 서버가 없다. `0.0.0.0`이나 `::`로 여는 코드를 넣지 않는다.
- 여는 주소는 `listAddresses()`가 준 것 가운데 사설 IPv4뿐이다. 다른 값이 섞여 있어도 걸러 낸다.
- 처리기가 불리기 전에 보낸 주소를 확인한다. 사설 주소가 아닌 요청은 처리기까지 가지 않는다.
- 처리기의 세 번째 인자 `info.local`은 `127.0.0.1` 문으로 들어온 요청에서만 참이다.
- 이미 켜져 있을 때의 `turnOn`은 남은 시간을 늘리지 않는다. 늘리는 것은 `extend`뿐이다.
- 제한 시간이 지났는지는 타이머뿐 아니라 요청·`status`·`turnOn`·`extend`·`urlsFor`가 불릴 때마다 확인한다.
- `close()` 뒤에는 다시 켤 수 없고 서버를 등록할 수 없다.

**서버 도구**
- `serveStatic`은 지정한 폴더 밖의 파일을 어떤 경로로도 내보내지 않는다(`..`, 역슬래시, 드라이브 글자, 점으로 시작하는 이름, 폴더 밖을 가리키는 링크 모두 거절). 보내지 못하면 아무것도 쓰지 않고 `false`를 돌려준다.
- `listen(server, port)`의 host 기본값은 `127.0.0.1`이다. 기본값을 바꾸지 않는다.
- `readJsonBody`는 크기를 바이트로 세고, 제한을 넘으면 본문을 버린다.
- `setCookie`가 붙이는 속성은 `Path=/; HttpOnly; SameSite=Lax`다. `Secure`나 `SameSite=Strict`로 바꾸면 두 앱의 응답 검사가 깨진다.
- `openBrowser`는 `http://`로 시작하는 정해진 모양의 주소만 연다. 실패해도 예외를 던지지 않는다.

## 이 폴더의 방식

- 화면에 나갈 수 있는 문구는 한국어로 쓰고, 오류 객체의 `message`에 그대로 담는다. 부르는 쪽이 그 문장을 바로 보여 줄 수 있어야 한다.
- 검사에서 바꿔 끼워야 하는 것(시계, 타이머, 내부 주소 찾기, 보낸 주소 알아내기, 프로세스 종료, 브라우저 실행)은 선택 인자로 받는다. 전역을 바꿔 치우지 않는다.
- 스위치에서 문을 여닫는 일은 `sync()` 하나로만 한다. 여닫는 작업은 줄을 세워 한 번에 하나씩 돈다. 문을 직접 열거나 닫는 새 경로를 만들면 "켜는 도중에 끄기"가 다시 깨진다.
- 스위치의 상태가 바뀌는 자리마다 `emit()`으로 알린다.

## 검사

- `test/shared-data.test.js`, `shared-address.test.js`, `shared-http.test.js`, `shared-switch.test.js`.
- 주소 판별을 고치면 허용 목록과 거절 목록 양쪽에 경우를 더한다. 거절 쪽에는 `010.0.0.1`, `0x7f.0.0.1`, `192.168.0.10:80`, `localhost`, 공인 주소, IPv6 같은 "비슷해 보이는 것"이 있어야 한다.
- 스위치를 고치면 "실제 내부 주소" 검사가 건너뜀이 아닌지 본다. 이 PC에 사설 IPv4가 없으면 건너뛰고, 그것은 통과가 아니다. 이 검사들은 실제로 내부 주소에 문을 열므로 학교·공용 와이파이에서 돌리지 않는다.
- 꼭 있어야 하는 경우: 확인 없이 켜기(거절), 꺼진 상태의 내부 주소 접속(연결 실패), 켠 뒤 접속, 끈 뒤 접속(연결 실패), 시간 초과, 연장, 켜는 도중에 끄기, 끈 직후 다시 켜기, 사설 주소가 아닌 "보낸 주소"(403), 주소 목록에 공인 주소가 섞인 경우.
- `serveStatic`을 고치면 폴더 밖으로 나가려는 경로들이 모두 `false`인지 본다.
