# 시스템 구성

## 프로그램 둘, 서버 넷

```
[첫 번째 노트북]                                         [두 번째 노트북 — 한 대로 할 때는 같은 PC]

시연 프로그램 (node src/demo.js, 프로세스 하나)            받는 쪽 프로그램 (node src/receiver/main.js)
 ├─ 진행 화면 서버   127.0.0.1:4170  ← 스위치에 등록 안 함     └─ 받는 쪽 서버  127.0.0.1:4180
 ├─ 1번 앱 서버      127.0.0.1:4173  ┐ 접속 스위치 하나에          └ 자기만의 접속 스위치에 등록
 └─ 2번 앱 서버      127.0.0.1:4174  ┘ 함께 등록

 브라우저: 진행 화면(프로젝터)                              브라우저: 받는 쪽 화면,
          1번·2번 앱 메인 화면(담임·학부모)                           첫 번째 노트북의 옆 사람 화면
```

- 모든 통신은 평문 HTTP와 JSON이다. Node.js의 `node:http` 서버와 내장 `fetch`만 쓴다. 화면은 순수 HTML/CSS/JavaScript다.
- 네 서버는 실행 직후 `127.0.0.1`에서만 듣는다. 접속 스위치를 켜면 스위치에 등록된 서버만 이 PC의 사설 IPv4 주소마다 같은 포트로 문을 하나씩 더 연다. 모든 주소(`0.0.0.0`)로 여는 일은 없다.
- 진행 화면 서버는 스위치에 등록하지 않는다. 그래서 스위치 상태와 무관하게 다른 기기에서는 연결 자체가 되지 않는다.
- 시연 프로그램과 받는 쪽 프로그램은 서로의 코드를 부르지 않는다. 둘 사이에는 HTTP 요청만 오간다.

## 누가 누구에게 말하는가

| 보내는 쪽 | 받는 쪽 | 방법 | 무엇을 |
|---|---|---|---|
| 앱 메인 화면, 옆 사람 화면(브라우저) | 자기가 열린 그 앱 서버 | HTTP, 쿠키 | 로그인, 조회, 성적 저장, AI 초안, 삭제. 옆 사람 화면만 요청에 `X-Demo-Screen: neighbor`를 붙인다 |
| 1번·2번 앱 서버 | 받는 쪽 서버 | HTTP `POST` | 성적 저장 뒤 학생 전체 기록(`/sheet/rows`), AI 초안 요청 때 번호·이름·평가·의견(`/ai/draft`) |
| 진행 화면(브라우저) | 진행 화면 서버 | HTTP, 1초마다 상태 읽기 + 단추마다 동작 요청 | 단계 이동, 스위치, 받는 쪽 주소, 공개, 2부, 전체 초기화 |
| 진행 화면 서버 | 1번·2번 앱 서버(`127.0.0.1`만) | HTTP | 공개 장면의 다섯 요청과 그 앞뒤의 로그인·로그아웃 |
| 진행 화면 서버 | 받는 쪽 서버 | HTTP | 받은 것 읽기(`GET /api/received`), 연결 확인(`GET /api/ping`), 전체 초기화 때 지우기(`POST /api/clear`) |
| 진행 화면 서버 | 1번·2번 앱 | 같은 프로세스 안의 함수 호출 | 접속 기록 구독, '가져간 것' 읽기, 전송 기록 읽기, 초기화, 가는 중인 전송 기다리기 |
| 진행 화면 서버 | 접속 스위치 | 같은 프로세스 안의 함수 호출 | 켜기·연장·끄기·상태 |
| 받는 쪽 화면(브라우저) | 받는 쪽 서버 | HTTP, 1초마다 | 받은 것 읽기, 스위치 조작, 지우기 |

받는 쪽 프로그램은 밖으로 어떤 요청도 보내지 않는다. 브라우저에서 받는 쪽으로 직접 가는 전송도 없다. 학생 기록이 받는 쪽에 닿는 길은 "브라우저 → 앱 서버 → 받는 쪽" 하나다.

## 함께 쓰는 상태 셋

시연 프로그램 안에는 `src/demo.js`가 한 번 만들어 여러 곳에 넘기는 객체가 셋 있다.

- **접속 스위치** — 두 앱 서버의 문을 여닫는다. 진행 화면 서버가 조작한다.
- **받는 쪽 주소** — 주소(host) 하나와 고정 포트. 두 앱은 보낼 때마다 이 값을 읽고, 바꿀 수 있는 것은 진행 화면 서버뿐이다.
- **두 앱** — 각자 학생 사본·로그인 상태·접속 기록·전송 기록을 가진다. 진행 화면 서버는 HTTP가 아니라 객체로 이것을 읽는다. 그래서 '접속 기록'과 '가져간 것'은 앱이 실제로 처리한 요청에서 직접 나온다.

상태는 모두 프로세스의 메모리에만 있다. 파일도 데이터베이스도 없다. 프로그램을 끄면 전부 사라지고, 다시 실행하면 같은 초기값으로 시작한다.

## 대표 흐름: 옆 노트북이 성적을 고친다

두 번째 노트북의 옆 사람 화면에서 '내 아이 성적 고치기'를 눌렀을 때(스위치 켜짐, 1번 앱).

1. 브라우저가 `http://<첫 번째 노트북 내부 주소>:4173`으로 `PUT /api/students/TEST-1001/ratings`를 보낸다. 쿠키와 `X-Demo-Screen: neighbor`가 붙는다.
2. 접속 스위치의 다른 기기 쪽 문이 받는다. 스위치가 켜져 있고 보낸 주소가 사설 주소이므로 앱 처리기에 넘긴다. 이때 "같은 PC 쪽 문으로 왔는가", "보낸 주소", "보낸 주소가 이 PC 자신인가"를 함께 넘긴다.
3. 앱 서버가 쿠키로 로그인 상태를 찾는다. 1번 앱은 요청자가 이 일을 해도 되는지 확인하지 않고 진행한다(2번 앱이라면 여기서 403으로 끝난다).
4. 메모리의 학생 기록이 바뀐다. 바뀐 기록을 200으로 돌려준다.
5. 응답과 별개로 앱 서버가 그 학생의 전체 기록을 받는 쪽의 `/sheet/rows`로 보낸다. 응답은 이 전송을 기다리지 않는다. 결과(성공·실패)는 앱의 전송 기록에 남는다.
6. 앱이 접속 기록 한 줄을 남기고 구독자에게 알린다. 진행 화면 서버가 두 앱의 기록을 들어온 순서대로 합친다.
7. 진행 화면이 다음 상태 읽기(1초 안)에서 그 줄을 '다른 기기'로 표시하고, 진행 화면 서버가 받는 쪽에 실제로 물어본 결과로 '받는 쪽에 도착한 것'을 한 줄 늘린다.
8. 받는 쪽 화면도 자기 서버를 1초마다 읽어 새 줄을 보여 준다.

## 모듈과 의존 방향

| 모듈 | 역할 | 의존하는 것 |
|---|---|---|
| `src/shared/` | 가상 데이터 생성, 주소 판별, 접속 스위치, HTTP 도구(본문 읽기·화면 파일·쿠키·브라우저 열기·시작 실패 안내), 포트 설정 | Node.js 내장 모듈만 |
| `src/app/` | 성적 관리 앱 하나를 만드는 코드와 화면 파일. 두 번 불러 1번·2번 앱을 만든다 | `shared` |
| `src/console/` | 진행 화면 서버, 화면에 나오는 모든 문구, 공개 장면, 2부 순서, 받는 쪽 주소 설정, 화면 파일 | `shared`. 앱은 가져오지 않고 만들어진 앱 객체를 넘겨받는다 |
| `src/receiver/` | 받는 쪽 서버·화면·진입점 | `shared` |
| `src/demo.js` | 시연 프로그램의 조립과 진입점 | `shared`, `app`, `console` |

방향은 한쪽이다. `shared`는 아무것도 가져오지 않고, `app`·`console`·`receiver`는 서로를 가져오지 않는다. 받는 쪽과 시연 프로그램이 공유하는 것은 `shared`의 가상 데이터 형식과 스위치 코드뿐이다.

## 경계를 넘는 것과 넘지 않는 것

| 경계 | 넘는 것 | 넘지 않는 것 |
|---|---|---|
| 이 PC → 같은 연결의 다른 기기 (스위치 켜짐) | 1번·2번 앱의 모든 화면과 요청 | 진행 화면 전부 |
| 받는 쪽 PC → 다른 기기 (받는 쪽 스위치 켜짐) | 연결 확인, 표에 줄 추가, AI 초안, 받은 것 읽기, 지우기 다섯 요청 | 받는 쪽 화면, 받는 쪽의 스위치 조작 |
| 앱 서버 → 받는 쪽 | 성적 저장 때 전체 기록, AI 초안 때 네 항목 | 삭제(아무것도 보내지 않는다), 조회, 로그인 |
| 진행 화면 서버 → 앱 서버(HTTP) | 공개 장면의 요청 | 그 밖의 모든 것(객체로 직접 읽는다) |
| 2부 | 없음 | 2부의 내용과 선택은 진행 화면 서버 밖으로 나가지 않는다 |
| 프로그램 → 인터넷 | 없음 | 전부 |

## 바깥 의존

런타임에 필요한 것은 Node.js 22 이상 하나와 브라우저(Chrome·Edge)다. 인터넷은 Node.js와 저장소를 내려받을 때만 필요하다. 기본 브라우저를 여는 데는 운영체제 명령(Windows `rundll32 url.dll,FileProtocolHandler`, macOS `open`, 그 밖 `xdg-open`)을 쓰고, 열지 못해도 프로그램은 계속 돌며 주소를 글자 창에 적어 준다.
