# src/receiver — 받는 쪽 프로그램

## 맡는 것

실제 온라인 표와 AI 서비스를 **교육용으로 흉내 낸** 별도 프로그램이다. 앱이 내보낸 데이터가 "다른 곳"에 실제로 도착해 남는다는 것을 보여 주는 것이 역할이다.

- `server.js` — `createReceiver(options)`. 받기(`/sheet/rows`, `/ai/draft`), 읽기(`/api/received`), 지우기(`/api/clear`), 연결 확인(`/api/ping`), 받은 내용의 확인 규칙, 미리 써 둔 초안, 자기 화면과 자기 스위치의 조작 경로(`/local/switch…`).
- `main.js` — `npm run receiver`의 진입점. 받는 쪽을 열고 기본 브라우저로 화면을 연다.
- `public/` — 받는 쪽 화면(`index.html`, `receiver.js`, `receiver.css`): 온라인 표·AI 서비스 두 탭, 지우기, 다른 기기 접속 스위치.

이 프로그램은 자기만의 접속 스위치를 하나 가진다. 시연 프로그램의 스위치와 독립이다.

## 맡지 않는 것

- 진짜 AI나 진짜 온라인 표를 부르지 않는다. **밖으로 어떤 요청도 보내지 않는다.** `fetch`, 소켓 연결, 자식 프로세스(브라우저 열기 제외)를 이 폴더에 넣지 않는다.
- 앱이나 진행 화면의 코드를 가져오지 않는다. 가져오는 것은 `src/shared/`뿐이다. 앱의 원본이 지워졌는지 알지 못하고, 알 방법도 없어야 한다.
- 받은 것을 파일에 쓰지 않는다. 메모리에만 둔다. 프로그램을 끄면 사라진다.
- 로그인이 없다. 누가 보냈는지는 보낸 쪽 주소로만 적는다.
- 보낸 주소가 사설 주소인지는 접속 스위치가 처리기보다 먼저 확인한다. 여기서 다시 만들지 않는다.

## 항상 성립해야 하는 것

**가상 데이터만 저장한다**
- 저장하기 전에 본문을 확인한다. 하나라도 어긋나면 400으로 거절하고 저장하지 않는다.
  - 항목 이름이 정해진 것과 정확히 같다(온라인 표 7개 `SHEET_KEYS`, AI 서비스 4개 `AI_KEYS`). 빠져도, 더 있어도 거절한다.
  - `id`가 `TEST-1001`~`TEST-1020`이다.
  - `name`이 `가상학생NN`, `className`이 `6학년 가상반`, `guardianName`이 `가상보호자NN`, `guardianPhone`이 `010-XXXX-00NN`이고 NN이 `id`의 끝 두 자리와 같다.
  - `ratings`가 정확히 5개 과목이고 값이 세 평가 중 하나다.
  - `comment`가 그 `id`의 가상 기록(`createStudents()`가 만든 것)에 들어 있는 문장과 글자까지 같다.
  - 본문이 16KB 이하다. 크기 초과도 413이 아니라 400으로 답한다.
- 이 확인을 느슨하게 만들지 않는다. 다른 기기도 이 요청들을 보낼 수 있으므로, 이 확인이 "실제 정보가 받는 쪽에 저장될 수 없다"의 유일한 근거다.
- 받는 본문이 가상 기록과 다를 수 있는 곳은 `ratings`의 다섯 값뿐이다. 종합의견을 포함해 글자를 그대로 받아 주는 항목은 없다(어떤 기능도 의견을 바꾸지 않으므로 정상적인 전송은 언제나 가상 문장을 보낸다). 길이 제한 같은 느슨한 확인으로 되돌리지 않는다.

**쌓는다**
- 같은 학생이 다시 와도 덮어쓰지 않고 뒤에 붙인다. 받은 순서를 유지한다.
- 항목은 `{ receivedAt, from, payload }`이고 `payload`는 받은 본문 그대로다. 가공하지 않는다.
- 표와 AI 서비스 각각 2,000개까지만 담고, 넘으면 507로 거절한다.
- 비워지는 것은 지우기 요청과 프로그램 종료뿐이다.

**초안은 미리 써 둔 문장이다**
- `buildDraft`는 받은 평가에서 `잘함`·`노력요함`인 과목 이름만 끼워 넣는다. 받은 이름·의견을 초안에 넣지 않는다.
- 초안은 `[사전 작성된 모의 응답]`으로 시작하고 실제 AI가 쓴 글이 아니라는 문장으로 끝난다. 이 표시를 떼지 않는다.

**누가 무엇을 쓸 수 있는가**
- 다른 기기(스위치가 켜져 있고 사설 주소일 때)가 쓸 수 있는 것은 다섯 요청뿐이다: `GET /api/ping`, `POST /sheet/rows`, `POST /ai/draft`, `GET /api/received`, `POST /api/clear`.
- 화면 파일과 스위치 조작(`/local/switch…`)은 `info.local`이 참일 때만, 곧 `127.0.0.1` 문으로 들어온 요청에만 답한다. 아니면 403이다. 같은 PC의 브라우저라도 내부 주소로 열면 403이다.
- 스위치 조작은 그에 더해 Host가 이 프로그램의 주소이고, `Origin`·`Sec-Fetch-Site`가 다른 사이트를 가리키지 않아야 한다. 화면을 여는 것은 Host만 본다.
- 스위치를 켜는 요청은 본문이 정확히 `{ confirmed: true }`를 가질 때만 받는다.
- 내보내는 화면 파일은 정해진 넷(`/`, `/index.html`, `/receiver.css`, `/receiver.js`)뿐이다. 폴더의 다른 파일은 주소로 열리지 않는다. 화면에 파일을 더하면 `SCREEN_FILES`에도 더한다.
- 새 경로를 더할 때는 "다른 기기도 쓰는 것"인지 "같은 PC에서만"인지를 먼저 정해 `openRoutes`와 `switchRoutes` 중 맞는 쪽에 넣는다. 기본은 같은 PC에서만이다.

**스위치**
- 실행 직후 꺼져 있다. 30분 뒤 스스로 꺼진다. 시연 프로그램의 스위치를 켜거나 연장해도 이쪽은 그대로다.
- 프로그램을 끝내면 스위치도 끄고 문을 모두 닫는다.

**시작**
- 포트를 열지 못하면 한국어로 알리고 번호 1로 끝난다.
- 포트는 `RECEIVER_PORT`(기본 4180)다. 시연 프로그램이 같은 번호로 보낸다. 한쪽만 바꾸면 아무것도 도착하지 않는다.

## 이 폴더의 방식

- 거절 문장은 무엇이 어긋났는지 알려 주되(빠진 항목 수, 정해지지 않은 항목 수), 받은 값을 문장에 되풀이하지 않는다.
- 화면은 콘텐츠 보안 정책(`script-src 'self'; style-src 'self'`)과 함께 나간다. HTML에 `<style>`, `style=`, `on…=`, 내용이 있는 `<script>`를 쓰지 않는다.
- 화면 상단에는 고정 표시(`교육용 실습 / 100% 합성 데이터 / 실제 개인정보 입력 금지`)와 "실제 온라인 표·AI 서비스가 아니라 흉내 낸 프로그램"이라는 문장을 둔다.
- 화면은 1초마다 받은 것과 스위치 상태를 읽어 그린다. 새로 도착한 것은 다시 열지 않아도 나타난다.
- 지우기와 스위치 켜기는 화면 안에서 한 번 더 물은 뒤 보낸다. 브라우저의 `confirm`을 쓰지 않는다.
- 화면에 타이핑하는 칸이 없다.

## 검사

- `test/receiver.test.js`(받기·읽기·지우기·거절·초안·화면 파일), `receiver-switch.test.js`(스위치와 같은 PC 전용 경로), `receiver-main.test.js`(실제 실행과 종료).
- 확인 규칙을 고치면 거절 경우를 하나하나 둔다: 번호 형식, 빠진 항목, 더 있는 항목, 번호가 다른 이름·연락처, 실제처럼 보이는 이름과 전화번호, 잘못된 과목·값, 가상 문장과 다른 의견(손으로 쓴 글, 다른 번호의 문장, 한 글자만 다른 문장), 16KB 초과, JSON이 아닌 본문. 거절 뒤 받은 것이 늘지 않았는지도 함께 본다.
- 검사에 쓰는 "실제처럼 보이는 값"도 지어낸 값만 쓴다.
- 꼭 있어야 하는 경우: 같은 학생을 두 번 받으면 두 줄, 지운 뒤 0건, 내부 주소로 들어온 화면 요청과 스위치 조작(403), 다른 Origin의 스위치 조작(403), 확인 없이 켜기(400), 사설 주소가 아닌 "보낸 주소"(403).
- 화면 파일에 바깥 주소가 없는지 보는 검사가 있다. 화면을 고치면 그 검사를 본다.
