# src/console — 진행 화면

## 맡는 것

- `server.js` — `createConsole(options)`. 진행 화면의 상태 읽기(`GET /api/state`)와 동작 요청(단계, 스위치, 받는 쪽 주소·연결 확인, 공개, 2부, 전체 초기화), 접근 제한, 화면 파일 내보내기.
- `content.js` — 진행 화면에 나오는 **모든 문구**: 단계(`STEPS`), 안내(`TEXT`), 공개 뒤의 설명(`REVEAL`), 2부(`PART2`), 마무리(`CLOSING`), 상단 고정 표시.
- `part2.js` — 2부의 순서 규칙. 순서는 화면이 아니라 여기서 지킨다.
- `reveal.js` — 공개 장면의 다섯 요청을 앱 하나에 실제로 보낸다.
- `receiver-address.js` — 받는 쪽 주소 설정 하나(두 앱과 함께 읽는다).
- `public/` — 진행 화면 파일(`index.html`, `console.js`, `console.css`, `favicon.ico`).
- `src/demo.js`(이 폴더 밖, 시연 프로그램의 진입점) — 접속 스위치, 받는 쪽 주소, 두 앱, 진행 화면 서버를 만들어 잇고 연다.

## 맡지 않는 것

- 권한 판단을 하지 않는다. 앱이 남긴 접속 기록의 '권한 확인 여부'를 공개 뒤에 보여 줄 뿐이다.
- 접속 기록을 만들지 않는다. 앱이 알려 주는 줄을 순서대로 합칠 뿐이다. '가져간 것'도 앱의 집계를 읽는다.
- 앱의 내부 상태를 만지지 않는다. 쓰는 것은 넘겨받은 앱 객체의 `subscribe`, `getNeighborSummary`, `getTransferLog`, `reset`, `whenIdle`과 공개 장면의 HTTP 요청뿐이다. `src/app/`을 가져오지 않는다(가져오는 것은 `src/demo.js`뿐이다).
- 받는 쪽의 코드를 가져오지 않는다. 받는 쪽과는 HTTP로만 말한다.
- 주소가 사설인지 판별하는 규칙, 스위치의 동작은 `src/shared/`의 것을 그대로 쓴다. 여기에 따로 만들지 않는다.

## 항상 성립해야 하는 것

**이 PC에서만**
- 진행 화면 서버는 접속 스위치에 등록하지 않는다. `src/demo.js`가 `listen(server, port, '127.0.0.1')`로만 연다.
- 모든 요청에서 Host가 `127.0.0.1:<포트>` 또는 `localhost:<포트>`인지 확인하고 아니면 403이다.
- `/api/` 아래 요청은 `Origin`이 있으면 이 화면의 주소와 같아야 하고, `Sec-Fetch-Site`가 있으면 `same-origin`이나 `none`이어야 한다. 아니면 403이다. 같은 PC의 다른 포트(두 앱의 화면)에서 온 요청도 여기서 막힌다.

**공개 전에는 드러내지 않는다**
- `revealed`가 거짓인 동안 상태 응답에 `permissionChecked`, `permissionLabel`, `appWithoutCheck`, `appWithCheck`, `REVEAL`의 문구가 들어가지 않는다.
- `STEPS`와 `TEXT`는 공개 전에도 나간다. 여기에 어느 앱이 어떤 앱인지 말하거나 짐작하게 하는 낱말(`허술`, `취약`, `안전`, `막아 둔`, `잘 막은`, `권한 확인`, `권한을 확인`, `확인 안 함`, `확인하지 않`, `비교용 예제`, `secure`, `unsafe`)을 넣지 않는다. 그런 내용은 `REVEAL`에만 둔다.
- `revealed`는 공개 요청이 끝났을 때만 참이 되고 전체 초기화에서만 거짓이 된다. 단계 이동으로 바뀌지 않는다.
- `public/`의 파일에는 `REVEAL`의 문구, 앱 이름('1번 앱'/'2번 앱'), 금지 낱말이 한 글자도 없어야 한다.

**결과를 꾸미지 않는다**
- 공개 표의 결과 번호와 내용은 `reveal.js`가 실제로 받은 값이다. 대답을 받지 못하면 `status`가 `null`이고 기대값으로 채우지 않는다.
- '받는 쪽에 도착한 것'은 받는 쪽에 실제로 물어본 결과다. 제대로 물어보지 못한 동안(`reachable`이 `true`가 아닐 때)에는 예전 결과를 보여 주지 않되, 0건이라고 하지도 않는다: 목록은 비우고 `sheetCount`·`aiCount`는 `null`로 싣는다. 화면은 `null`을 "확인하지 못함"으로 적고, "아직 도착한 것이 없습니다."는 받는 쪽이 실제로 대답했을 때만 쓴다. 주소가 바뀌거나 지웠으면 그 전에 시작한 질의의 결과는 버린다(세대 번호).
- 연결 확인은 200이 왔더라도 본문이 `{ ok: true, service: "receiver" }`가 아니면 실패다.
- `public/`의 파일에는 결과 번호 숫자(200·401·403·404), 단계 문구, 2부 내용, 마무리 문장, 스위치·받는 쪽 안내가 글자로 없어야 한다. 화면은 상태를 받아 그리기만 한다.

**밖으로 보내는 곳**
- 이 폴더가 보내는 요청은 받는 쪽으로 셋(`/api/received`, `/api/ping`, `/api/clear`), 두 앱으로 하나(공개)뿐이다.
- 받는 쪽으로 보낼 때는 매번 `receiverAddress.base()`로 주소를 만든다(그때마다 같은 PC·사설 IPv4인지 다시 확인한다).
- `runRevealOn`은 `http://127.0.0.1:<포트>` 모양의 주소가 아니면 예외를 던진다.
- 모든 `fetch`에 `redirect: 'error'`와 시간 제한을 붙인다.
- `part2.js`는 어디에도 요청을 보내지 않는다. 2부를 처리하는 동안 받는 쪽에 아무것도 가지 않는다.

**받는 쪽 주소**
- 바꿀 수 있는 것은 주소(host)뿐이고 포트는 처음 정한 값으로 고정이다. 받아들일 수 없는 값이면 바꾸지 않고 이유를 돌려준다.
- 주소를 바꾸면 예전 주소의 '도착한 것'과 연결 확인 결과를 버린다.

**공개**
- 다섯 시도는 `content.js`의 `REVEAL.attempts`에 있는 방식·경로·본문 그대로 보낸다. 옆 사람 화면 표시를 붙이지 않는다('가져간 것'에 세지 않기 위해).
- 누를 때마다 새로 로그인하고 끝나면 로그아웃한다. 이미 보내는 중이면 409다.
- 도중에 전체 초기화가 있었으면 결과를 쓰지 않는다.

**2부**
- 여덟 칸의 순서와 조건은 `part2.js`만 정한다. 첫 선택 전에는 맥락을 열 수 없고, 맥락 네 개를 다 열기 전에는 다시 선택할 수 없고, 첫 선택은 맥락을 열기 시작하면 고정된다.
- `view()`는 지금까지 열린 것만 담는다. 아직 열지 않은 사실·해석·선택지·맥락·설명은 응답에 싣지 않는다.
- 두 선택이 같은지 다른지만 알린다. 어느 선택이 맞다고 표시하는 값을 만들지 않는다.
- `PART2`에 병명, 분류, 점수, 등급을 넣지 않는다.

**전체 초기화**
- 순서: 보내는 중인 공개가 끝나기를 기다리기 → 두 앱 초기화와 단계·2부·공개·기록 되돌리기 → 가는 중인 전송 기다리기(최대 3.5초) → 받는 쪽에 지우기 요청. 이 순서를 바꾸지 않는다.
- 공개를 기다리는 것은 공개의 남은 요청이 초기화 뒤에 앱에 도착하지 않게 하기 위해서다. 그 공개의 결과는 버린다. 초기화하는 동안 들어온 공개 요청은 409로 거절한다.
- 스위치와 받는 쪽 주소를 건드리지 않는다.
- 받는 쪽을 지우지 못해도 나머지 초기화는 이루어지고 200으로 답하며, 지우지 못했다는 문장을 싣는다. 이유는 실제 결과대로 나눈다: 대답이 없었으면 `receiverAnswered: false`와 닿지 못함 표시, 대답은 왔지만 200이 아니었으면 `receiverAnswered: true`와 실제로 받은 `receiverStatus`. 대답이 온 경우를 "닿지 못했다"고 적지 않는다.

**상태 읽기는 밀리지 않는다**
- `GET /api/state`는 받는 쪽 질의가 진행 중이어도 0.3초만 기다리고 직전 결과로 답한다. 받는 쪽에는 1초에 한 번을 넘겨 묻지 않고, 한 번에 하나만 묻는다. 받는 쪽이 꺼져 있을 때 진행 화면이 멈추지 않게 하는 장치다.

**시연 프로그램의 시작(`src/demo.js`)**
- 두 앱과 진행 화면 셋 중 하나라도 열지 못하면 이미 연 것을 모두 닫고 실패한다.
- `src/demo.js`는 불러오기만 해서는 아무것도 열지 않는다. 직접 실행했을 때만 `main()`이 돈다.
- 스위치를 켠 채 시작하는 길을 만들지 않는다.

## 이 폴더의 방식

- 문구를 고칠 때는 `content.js`만 고친다. `server.js`나 `public/`에 문장을 적지 않는다. `STEPS`의 `id`는 프로그램이 쓰는 이름이므로 바꾸지 않는다.
- 발표자가 말할 문장(`say`), 공개의 설명과 시도 이름, 2부 선택지와 문구는 발표 안내서에 글자 그대로 있어야 한다. 문구를 고치면 그 문서의 같은 문장을 함께 고친다.
- 동작 요청은 성공이든 거절이든 `state`를 함께 돌려준다. 거절은 `Refusal(번호, 한국어 문장)`을 던져서 한다.
- 진행 화면 파일은 콘텐츠 보안 정책(`script-src 'self'; style-src 'self'`)과 함께 나간다. HTML에 `<style>`, `style=`, `on…=`, 내용이 있는 `<script>`를 쓰지 않고, 스크립트에서 `.style`을 만지지 않는다. 모양은 클래스로 바꾼다.
- 화면 스크립트는 서버가 준 값을 `textContent`로만 넣는다. 브라우저의 `confirm`·`alert`·`prompt`를 쓰지 않고 화면 안에서 확인을 받는다. 스위치를 켜는 요청은 확인을 누른 자리에서만 보낸다.
- 타이핑하는 칸은 받는 쪽 주소 하나뿐이다.
- 화면은 1초마다 상태를 읽고, 남은 시간은 0.25초마다 스스로 줄여 그린다. 단추 동작이 돌려준 상태가 그 사이에 도착한 읽기 결과보다 새것이므로 읽기 결과를 버린다.
- 화면은 프로젝터에 나간다. 큰 글씨와 높은 대비를 유지하고, 망설여지면 단추를 줄이고 상태 표시를 키운다. 화면 글에 개발 용어를 쓰지 않는다.

## 검사

- `test/console-api.test.js`(상태와 동작 전부), `console-reveal.test.js`, `console-part2.test.js`, `console-pages.test.js`(화면 파일), `console-demo.test.js`(시작·종료, 진행 화면이 내부 주소로 열리지 않음), 그리고 두 프로그램을 함께 띄우는 `e2e-talk.test.js`, `e2e-edges.test.js`.
- 검사 도구 `test/console-helpers.js`의 `startRig`가 시연 프로그램 전체를 포트 0으로 띄운다. 받는 쪽 포트는 0일 수 없어서 받는 쪽을 먼저 띄워 그 번호를 넘긴다. 받는 쪽이 꺼진 상황은 `receiver: false`로 만든다.
- 꼭 있어야 하는 경우: 공개 전 상태 응답 전체에 금지 낱말과 권한 확인 항목이 없음, 공개 뒤에는 있음, 전체 초기화 뒤 다시 없음. 스위치를 확인 없이 켜기(400). 받는 쪽 주소에 이름·공인 주소·포트 붙은 값(400, 값 불변). 받는 쪽이 꺼졌을 때의 상태·연결 확인·전체 초기화. 2부의 순서 위반 하나하나(409). 다른 Host·다른 Origin의 요청(403). 스위치가 켜진 채 내부 주소로 진행 화면에 접속(연결 실패).
- 접속 기록을 확인하는 검사는 "보낸 요청의 장부"와 기록을 통째로 비교한다. 줄 수만 세지 않는다.
- 문구나 화면의 단추 이름을 고쳤으면 `test/docs.test.js`가 통과하는지 본다.
