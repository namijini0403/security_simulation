# 규칙

## 통과해야 하는 문

- 변경을 끝냈다고 하려면 `npm test`가 번호 0으로 끝나고 실패가 0이어야 한다. (`npm test`)
- **건너뜀은 통과가 아니다.** 이 PC에 사설 IPv4 주소가 없으면 "실제 내부 주소" 검사들이 건너뜀으로 표시된다. 접속 스위치나 서버를 여는 코드를 고쳤다면 내부 주소가 있는 PC에서 건너뜀 0으로 확인한다. (검사 출력의 `skipped` 숫자)
- 하지 못한 확인을 했다고 적지 않는다. 두 대로 확인하지 못했거나 Mac에서 실행해 보지 못했으면 `TEST_REPORT.md`, README, 안내서에 "확인하지 못함"으로 적는다. "통과"라고 적는 항목에는 실행한 명령과 나온 결과를 함께 적는다. (문서 검사가 README·발표 안내서·연결 안내서에 "확인하지 못했습니다" 문장이 있는지 본다)

## 부품과 실행 환경

- `package.json`에 `dependencies`·`devDependencies`를 넣지 않는다. Node.js 22 이상에 들어 있는 모듈만 쓴다. 검사 도구도 내장 `node:test`다. (`package.json`, `node_modules` 폴더가 생기면 위반)
- 모듈 형식은 ES 모듈이다(`"type": "module"`). 화면 스크립트는 모듈이 아닌 일반 스크립트다.
- Node.js 최소 버전 22는 `package.json`의 `engines`, `src/shared/http.js`의 `REQUIRED_NODE_MAJOR`, 실행 파일 네 개의 버전 확인에 각각 적혀 있다. 바꾸려면 모두 함께 바꾼다. (한 곳만 바꾸면 실행 파일은 통과시키고 프로그램이 거절하거나 그 반대가 된다)
- 설정은 환경 변수 다섯 개뿐이다(`CONSOLE_PORT`, `APP1_PORT`, `APP2_PORT`, `RECEIVER_PORT`, `DEMO_NO_BROWSER`). 설정 파일을 만들지 않는다. 스위치를 켠 채 시작하게 하거나 받는 쪽 주소를 미리 정하는 설정을 더하지 않는다.
- 배포 설정 파일(호스팅 서비스 설정, 컨테이너 정의, 공개 주소에 올리는 작업 흐름)을 저장소에 넣지 않는다.
- 데이터를 파일, 데이터베이스, 브라우저 저장소에 쓰지 않는다. 상태는 프로세스 메모리에만 둔다.

## 모듈 경계

- `src/shared/`는 다른 `src/` 폴더를 가져오지 않는다.
- `src/app/`, `src/console/`, `src/receiver/`는 서로를 가져오지 않는다. 가져올 수 있는 것은 `src/shared/`뿐이다.
- 진행 화면 서버가 앱을 쓰는 길은 `src/demo.js`가 넘겨준 앱 객체의 함수(`subscribe`, `getNeighborSummary`, `getTransferLog`, `getAccessLog`, `reset`, `whenIdle`)와 공개 장면의 HTTP 요청뿐이다. 앱의 내부 상태를 직접 만지지 않는다.
- 두 앱을 만드는 설정에서 달라도 되는 것은 `label`, `checkPermission`, `cookieName` 셋뿐이다. 앱 코드 안에서 `checkPermission`을 읽는 곳은 권한 판단과 접속 기록의 '권한 확인 여부' 두 군데로 한정한다. 그 밖의 분기(경로, 응답 모양, 문구, 전송)를 만들면 두 앱이 달라진다. (두 앱의 응답을 통째로 비교하는 검사)
- 불러오는 것만으로 서버가 열리거나 프로그램이 끝나는 모듈을 만들지 않는다. 포트를 여는 것은 진입점(`src/demo.js`의 직접 실행, `src/receiver/main.js`)이 함수를 불렀을 때뿐이다.

## 서버를 여는 방법

- 서버를 여는 길은 둘뿐이다. 접속 스위치의 `listen`(등록된 서버), 그리고 `src/shared/http.js`의 `listen(server, port)`(같은 PC 전용). `server.listen()`을 직접 부르거나 host에 `0.0.0.0`, `::`, 빈 값을 주지 않는다. (실제 내부 주소 검사, 진행 화면이 내부 주소로 열리지 않는다는 검사)
- 진행 화면 서버는 접속 스위치에 등록하지 않는다.
- 여러 서버를 차례로 열다가 하나라도 실패하면 이미 연 것을 모두 닫고 한국어 안내를 낸 뒤 번호 1로 끝난다. 일부만 뜬 채로 계속 돌게 두지 않는다.
- "같은 PC에서만 허용"은 접속 스위치가 넘겨주는 `info.local`(어느 문으로 들어왔는가)로 판단한다. 접속 기록 표시용인 `samePc`(보낸 주소가 이 PC 것인가)나 요청에 적힌 값으로 판단하지 않는다.

## 밖으로 보내는 요청

- 받는 쪽으로 보내는 모든 요청은 보내기 직전에 `receiverBaseUrl()`(또는 그것을 거치는 `receiverAddress.base()`)로 주소를 만든다. 주소 글자를 직접 이어 붙여 `fetch`에 넘기지 않는다.
- 모든 `fetch`에 `redirect: 'error'`와 시간 제한(`AbortSignal.timeout`)을 붙인다.
- 새로 요청을 보내는 자리를 만들지 않는다. 지금 있는 다섯 자리(앱의 전송, 받은 것 읽기, 연결 확인, 지우기, 공개) 말고 `fetch`·소켓·자식 프로세스로 밖과 통신하는 코드가 생기면 위반이다. 자식 프로세스는 기본 브라우저를 여는 한 곳뿐이다.
- 받는 쪽 프로그램(`src/receiver/`)에는 밖으로 나가는 요청이 하나도 없어야 한다.

## 두 앱이 내보내는 것

브라우저로 나가는 모든 것 — 화면 파일의 내용과 파일 이름, 경로, 응답 본문, 머리글, 쿠키 이름, 오류 문구 — 에 적용한다. 코드 안의 변수 이름은 자유다.

- 두 앱의 화면 파일은 바이트까지 같다. 앱마다 다른 화면 파일을 두지 않는다. 앱 이름('1번 앱'/'2번 앱')은 파일에 적지 않고 `GET /api/app`에서 받아 온다.
- 금지 낱말: `unsafe`, `insecure`, `secure`, `vuln`, `leak`, `guard`, `protect`, `safe`, `weak`, `strict`, `취약`, `안전`, `허술`, `막아`, `보호`, `보안`. 화면 파일에서는 `guardianName`·`guardianPhone`·`보호자`만 예외로 떼고 검사한다. (화면 파일 검사, 응답 비교 검사)
- 같은 요청에 대한 두 앱의 응답은 권한 표가 다르다고 정한 칸에서만 다르고, 그 칸에서도 결과 번호와 거절 문구만 다르다. 머리글 구성, 항목 순서, 쿠키 속성이 달라서는 안 된다.
- 화면 파일에 결과를 미리 적지 않는다. 옆 사람 화면 파일에는 결과 번호(200·401·403·404 등), `가상학생`·`가상보호자`·`010-`, '성공'·'실패'가 글자로 있으면 안 된다(스크립트의 비교용 200 하나만 예외).
- 서버가 준 값은 `textContent`로만 그린다. `innerHTML`, `outerHTML`, `insertAdjacentHTML`, `document.write`, `eval`을 쓰지 않는다.
- 타이핑하는 칸은 로그인 폼 안의 두 칸뿐이다. `textarea`, `contenteditable`, `type="file"`, `prompt()`, 스크립트로 만든 `input`을 두지 않는다.
- 옆 사람 화면 표시(`X-Demo-Screen: neighbor`)는 옆 사람 화면만 붙이고, 그 스크립트는 요청을 한 곳(`ask`)에서만 보낸다. 메인 화면 파일에는 이 표시나 `neighbor`라는 글자가 없어야 한다.
- 화면 파일은 바깥 주소(`http://`, `https://`, `//`로 시작하는 주소)를 가리키지 않는다.
- 앱 화면은 다른 곳으로 보낸다는 사실을 알리는 문구를 넣지 않는다. 성적 저장 뒤의 문구는 "저장되었습니다"뿐이다.

## 진행 화면 문구

- 화면에 나오는 문구는 모두 `src/console/content.js`에 둔다. 진행 화면 파일(`src/console/public/`)에는 단계 문구, 2부 내용, 마무리 문장, 스위치·받는 쪽 안내, 앱 이름, 결과 번호 숫자(200·401·403·404)를 적지 않는다. 화면은 서버 상태를 받아 그리기만 한다. (진행 화면 파일 검사)
- `STEPS`와 `TEXT`는 공개 전에도 화면에 나온다. 여기에 다음 낱말을 넣지 않는다: `허술`, `취약`, `안전`, `막아 둔`, `잘 막은`, `unsafe`, `insecure`, `secure`, `권한 확인`, `권한을 확인`, `확인 안 함`, `확인하지 않`, `비교용 예제`. 어느 앱이 어떤 앱인지 말하거나 짐작하게 하는 내용은 `REVEAL`에만 둔다.
- 진행 화면 서버의 상태 응답에는 공개 전에 `permissionChecked`, `checkPermission`, `appWithoutCheck` 같은 항목이 들어가면 안 된다. 공개 뒤에만 싣는다.
- 진행 화면과 받는 쪽 화면의 HTML에는 `<style>`, `style=` 속성, `on…=` 속성, 내용이 있는 `<script>`를 쓰지 않는다. 스크립트에서 `.style`을 만지지 않고 클래스로 바꾼다. 브라우저의 `confirm`·`alert`·`prompt`를 쓰지 않고 화면 안에서 확인을 받는다. (콘텐츠 보안 정책이 막고, 화면 파일 검사가 잡는다)
- 2부 문구에 병명, 분류, 점수, 등급을 넣지 않는다.

## 안내 문서와 화면 글자

`README.md`, `PRESENTER_GUIDE.md`, `NETWORK_GUIDE.md`는 검사 대상이다.

- 세 문서에서 **작은따옴표로 묶은 말은 화면에 실제로 나오는 글자**여야 한다. 다른 용도로 작은따옴표를 쓰지 않고, 줄마다 짝이 맞아야 한다.
- 단추·칸·단계 이름을 바꾸면 세 문서의 같은 글자를 함께 바꾼다. 발표자가 말할 문장(`STEPS`의 `say`), 공개 장면의 설명과 시도 이름, 2부 선택지와 문구, 스위치 경고는 발표 안내서에 글자 그대로 있어야 한다.
- 문서에 적는 포트는 기본 포트 넷(4170, 4173, 4174, 4180) 중 하나, 계정은 실제로 로그인되는 값, 학생 번호는 `TEST-1001`~`TEST-1020`이어야 한다.
- 발표 안내서와 연결 안내서에 "반드시 남습니다", "항상 접속됩니다", "방화벽을 끄면 됩니다" 같은 단정·권유 문장을 쓰지 않는다.

## 더블클릭 실행 파일

- `.bat`는 UTF-8(BOM 없음), 줄 끝 CRLF, 첫 줄 `@echo off`. `exit /b %RC%` 줄까지의 실행 부분에는 ASCII 글자만 쓴다. 한국어 문구는 그 아래 `::[이름]문구` 줄에만 둔다. `goto`와 `:이름표`를 쓰지 않는다.
- `.command`는 줄 끝 LF, 첫 줄 `#!/bin/bash`, 실행 권한 필요. 줄 끝은 `.gitattributes`가 고정한다.
- 실행 파일이 하는 일은 자기 폴더로 가서 Node.js를 찾고 버전을 확인한 뒤 프로그램을 실행하는 것뿐이다. `netsh`, `runas`, `sudo`, `powershell`, `curl`, `wget`, `winget`, `brew`, `reg add` 등 설정을 바꾸거나 권한을 올리거나 무언가를 내려받는 명령을 쓰지 않는다.
- 시연용과 받는 쪽용 실행 파일은 실행 대상 경로와 프로그램 이름만 다르고 나머지는 글자까지 같다. 한쪽만 고치지 않는다.

## 검사를 쓰는 방법

- 검사는 실제 서버를 띄워 실제 요청을 보낸다. 서버를 흉내 낸 가짜 객체로 권한이나 스위치를 확인하지 않는다.
- 검사가 여는 포트는 항상 0(빈 포트 자동 선택)이다. 기본 포트(4170 등)를 검사에서 열지 않는다. 받는 쪽 포트만은 0일 수 없으므로 먼저 빈 포트에 받는 쪽(또는 임시 서버)을 띄워 그 번호를 넘긴다.
- 검사는 브라우저를 열지 않는다(`openBrowser: false` 또는 `DEMO_NO_BROWSER=1`).
- 성적 저장 뒤 받는 쪽의 내용이나 전송 기록을 확인하는 검사는 먼저 앱의 `whenIdle()`을 기다린다.
- 스위치의 시간 검사는 실제 30분을 기다리지 않고 주입한 시계·타이머나 짧은 제한 시간으로 한다.
- 실제 내부 주소가 필요한 검사는 주소가 없으면 이유("확인하지 못함")를 달아 건너뛴다. 조용히 통과시키지 않는다.

## 저장소

- 커밋 메시지는 한국어로 쓴다.
- `main`이 공개 저장소 `github.com/namijini0403/security_simulation`의 `main`을 따라간다. 공개 저장소이므로 올리기(push) 전에 사용자에게 확인을 받는다.
- 실제 이름·연락처처럼 보이는 값을 코드, 검사, 문서 어디에도 커밋하지 않는다. 검사에서 "실제처럼 보이는 값이 거절되는지" 볼 때도 `김보호자`, `010-1234-5678` 같은 지어낸 값만 쓴다.
