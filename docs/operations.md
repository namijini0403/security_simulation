# 실행과 운영

배포는 없다. 코드는 공개 저장소 `https://github.com/namijini0403/security_simulation`에 두고, 각 노트북에서 내려받아 그 노트북에서 실행한다.

## 준비

1. Node.js 22 이상을 설치한다(<https://nodejs.org>의 LTS 설치 파일). 그 밖에 설치할 것은 없다. `npm install`은 필요 없다.
2. 저장소를 내려받는다(ZIP을 받아 **압축을 모두 푼다**, 또는 `git clone`). 압축 파일 안에서 바로 실행하면 실행 파일이 프로그램 파일을 찾지 못한다.
3. 두 대로 진행하면 두 번째 노트북에도 1, 2를 똑같이 한다. 인터넷이 필요한 것은 여기까지다. 발표 전에 끝내 둔다.

확인: 저장소 폴더에서 `node -v`가 `v22` 이상을 내면 된다. 버전 관리 도구(fnm, nvm)로 설치해 일반 셸에서 `node`를 찾지 못하면 Node.js 설치 폴더(그 안에 `node`와 `npm`이 함께 있다)를 PATH 앞에 붙인 뒤 실행한다. Windows에서 `fnm exec --using=22 npm test`는 fnm이 `npm`을 실행하지 못해 실패한다(`fnm exec --using=22 node …`는 된다). 더블클릭 실행 파일은 스스로 찾는다.

## 명령

저장소 폴더에서 실행한다.

| 명령 | 하는 일 | 더블클릭 파일 (Windows / macOS) |
|---|---|---|
| `npm run demo` | 시연 프로그램: 진행 화면 + 1번 앱 + 2번 앱. 기본 브라우저로 진행 화면을 연다 | `시연 시작.bat` / `시연 시작.command` |
| `npm run receiver` | 받는 쪽 프로그램. 기본 브라우저로 받는 쪽 화면을 연다 | `받는 쪽 시작.bat` / `받는 쪽 시작.command` |
| `npm test` | 자동 검사 전체(약 30초). 번호 0, 실패 0이어야 한다 | 없음 |
| `node --test test/e2e-talk.test.js test/e2e-edges.test.js` | 두 프로그램을 실제로 함께 띄우는 검사만(10초 안쪽) | 없음 |

- 두 프로그램은 어느 쪽을 먼저 켜도 된다. 받는 쪽이 꺼져 있어도 시연 프로그램은 시작되고, 나중에 받는 쪽을 켜면 다시 실행하지 않아도 이어진다.
- 같은 프로그램을 두 번 켜면 두 번째는 "○○번 포트를 이미 다른 프로그램이 쓰고 있어서 시작할 수 없습니다"를 내고 번호 1로 끝난다. 먼저 켠 창을 닫는다.
- 글자가 나오는 창이 프로그램 그 자체다. 닫으면 프로그램이 끝난다.

### `npm test`를 돌리기 전에

검사는 이 PC의 내부 주소에 임의 포트로 문을 수 초씩 열었다 닫는다. **학교·공용 와이파이에 연결된 채로 돌리지 않는다.** 와이파이를 끄거나 전용 연결(휴대폰 핫스팟)에서 돌린다. 와이파이를 끄면 "실제 내부 주소" 검사가 건너뜀이 되고, 이것은 통과가 아니다. 접속 스위치를 고쳤다면 전용 연결에서 돌려 건너뜀 0을 확인한다.

## 주소와 설정

| 화면 | 기본 주소 | 환경 변수 | 다른 기기에서 |
|---|---|---|---|
| 진행 화면 | `http://127.0.0.1:4170` | `CONSOLE_PORT` | 열리지 않는다 |
| 1번 앱 | `http://127.0.0.1:4173` | `APP1_PORT` | 진행 화면의 스위치가 켜졌을 때만 |
| 2번 앱 | `http://127.0.0.1:4174` | `APP2_PORT` | 진행 화면의 스위치가 켜졌을 때만 |
| 받는 쪽 | `http://127.0.0.1:4180` | `RECEIVER_PORT` | 받는 쪽 화면의 스위치가 켜졌을 때만 |

- 옆 사람 화면은 앱 주소 끝에 `/neighbor`를 붙인다.
- 포트 환경 변수는 검사를 위한 것이다. 값은 0~65535의 숫자이고 0은 "빈 포트 자동 선택"이다. 숫자가 아니면 한국어 안내를 내고 끝난다.
- `RECEIVER_PORT`는 두 프로그램이 **같은 값**을 가져야 한다. 시연 프로그램에게는 "보낼 곳의 포트", 받는 쪽 프로그램에게는 "열 포트"다. 시연 프로그램에서는 0일 수 없다(1~65535). 두 대로 진행할 때 한쪽만 바꾸면 전송이 닿지 않는다.
- 문서와 화면 안내가 모두 기본 포트를 전제로 한다. 발표에서는 포트를 바꾸지 않는다.
- `DEMO_NO_BROWSER=1`이면 브라우저를 자동으로 열지 않는다(검사와 자동 실행용).
- 계정: 담임 `teacher` / `teacher1234`, 학부모 `parent01`~`parent20` / `demo1234`.

스위치의 제한 시간(30분), 알림 시점(2분), 받는 쪽 주소는 환경 변수로 바꿀 수 없다. 받는 쪽 주소는 진행 화면에서만 바꾼다.

## 두 대로 진행할 때의 순서

순서가 바뀌면 중간 확인이 실패한다.

1. 두 노트북을 **전용 연결**(휴대폰 핫스팟, 학교 통신망에 연결하지 않은 별도 공유기)에 붙인다. 학교·공용 와이파이에서는 하지 않는다.
2. 두 번째 노트북에서 받는 쪽 프로그램을 켠다. 받는 쪽 화면에서 '켜기' → 경고 확인. 화면에 나온 내부 주소를 적어 둔다.
3. 첫 번째 노트북에서 시연 프로그램을 켠다. 진행 화면의 '받는 쪽 주소'에 2에서 적은 주소를 넣고 '주소 적용', '연결 확인'. (2를 하기 전에는 연결 확인이 실패한다.)
4. 진행 화면에서 '다른 기기 접속'을 켠다. 화면에 나온 '두 번째 노트북에 입력할 주소'를 두 번째 노트북의 브라우저에 넣어 옆 사람 화면을 연다. (스위치를 켜기 전에는 이 주소가 화면에 나오지 않고, 열리지도 않는다.)
5. 프로젝터는 첫 번째 노트북에만 연결한다.

- 두 스위치는 각각 30분 뒤에 꺼진다. 연장도 각 화면에서 따로 누른다.
- 방화벽 알림이 뜨면 전용 연결(개인 네트워크)에만 허용한다. 방화벽을 끄지 않는다. 프로그램은 방화벽 설정을 건드리지 않는다.
- 같은 연결에 있어도 방화벽이나 기기 간 통신을 막는 와이파이 때문에 접속되지 않을 수 있다. 발표 전에 실제 장비로 해 본다. 1분 안에 해결되지 않으면 한 대로 진행한다.

## 한 대로 진행할 때

두 프로그램을 같은 PC에서 켜고, 옆 사람 화면은 진행 화면의 새 창 열기 단추나 `http://127.0.0.1:4173/neighbor`로 연다. 스위치를 켤 필요가 없다. 옆 사람 화면과 1번 앱 화면을 같은 브라우저에서 열면 로그인을 함께 쓰므로, 번거로우면 옆 사람 화면만 다른 브라우저에서 연다. "다른 기기에서 실제로 열린다"는 순간은 보여 줄 수 없다.

## 되돌리기

| 하고 싶은 것 | 방법 | 돌아가는 것 | 그대로인 것 |
|---|---|---|---|
| 2부만 다시 | 진행 화면의 '2부만 처음으로' | 2부의 진행과 선택 | 나머지 전부 |
| 발표를 처음부터 | 진행 화면의 '전체 초기화' → '초기화 실행' | 학생 기록, 로그인, 접속 기록, 가져간 것, 단계, 2부, 공개 상태, 받는 쪽의 받은 내용 | 스위치 상태와 남은 시간, 받는 쪽 주소 |
| 받는 쪽만 비우기 | 받는 쪽 화면의 '받은 내용 모두 지우기' | 받는 쪽의 받은 내용 | 나머지 전부 |
| 전부 처음 상태로 | 프로그램을 끄고 다시 켠다 | 위 전부 + 스위치 꺼짐 + 받는 쪽 주소 `127.0.0.1` | 없음 |

- 전체 초기화 때 받는 쪽에 닿지 못하면 "받는 쪽은 지우지 못했습니다. 받는 쪽 화면에서 직접 지우세요"가 나온다. 받는 쪽 화면에서 직접 지운다.
- 전체 초기화 뒤에는 열어 둔 앱 화면에서 로그아웃 후 다시 로그인한다.
- 두 대로 진행하다 시연 프로그램을 다시 켰다면 받는 쪽 주소를 다시 넣고 스위치를 다시 켠다.
- 받는 쪽 프로그램을 다시 켜면 받은 내용이 사라지고 받는 쪽 스위치도 꺼진다.

## 끝내기

1. 두 화면에서 '다른 기기 접속'을 끈다.
2. 두 프로그램의 글자 창을 닫는다(또는 Ctrl+C. Windows에서 계속할지 묻는 문장이 나오면 Y를 누르거나 창을 닫는다).
3. 전용 연결(핫스팟)을 끈다.

프로그램을 끄면 데이터와 열려 있던 접속이 함께 사라진다. 끝난 뒤 정리할 파일은 없다. 종료에는 1~3초가 걸리고, 정리가 늦어져도 3초 뒤에는 프로세스가 끝난다.

## 저장소에 올리기

`main`이 공개 저장소의 `main`을 따라간다. 올리기 전에 `npm test`를 통과시키고, 공개 저장소이므로 사용자에게 확인을 받는다. 올린 뒤 두 번째 노트북에서는 다시 내려받아야 새 코드가 적용된다(두 노트북의 코드가 다르면 받는 쪽이 정해진 항목과 다른 본문을 거절할 수 있다).
