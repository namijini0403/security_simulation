# 0005 전송 장면에는 두 앱의 차이를 두지 않는다

## 상황

④ 장면은 성적 저장과 AI 초안 요청이 학생 기록을 다른 곳(받는 쪽)으로 조용히 내보내고, 앱에서 지워도 그곳에는 남는다는 것을 보여 준다. 2번 앱이 "잘 만든 앱"이라면 이 장면에서도 무언가 다르게 해야 하는가가 문제였다(동의 화면, 이름 가리기, 덜 보내기 등).

## 결정

다른 곳으로 보내는 동작은 두 앱이 완전히 같다. 2번 앱도 담임이 성적을 저장하면 보호자 연락처까지 든 전체 기록을 받는 쪽으로 보낸다. 공개 장면에서 "데이터를 다른 곳으로 보내는 것은 두 앱이 똑같습니다. 잘 막은 앱이라도 밖으로 나간 데이터는 별개의 문제입니다."라고 밝힌다.

## 버린 대안

- **2번 앱에 동의 화면이나 이름 가리기**: 청중이 "이렇게 하면 외부로 보내도 괜찮다"로 받아들인다. 이 시연이 전하려는 것은 "접근을 잘 막는 것"과 "데이터가 밖으로 나가는 것"이 별개의 문제라는 점인데, 둘이 하나의 "잘 만든 앱" 안에서 함께 해결되는 것처럼 보이게 된다.
- **2번 앱은 아예 보내지 않기**: 같은 오해를 더 강하게 만든다. 또 두 앱의 코드가 권한 확인 말고 다른 데서도 갈라진다.

## 결과

- 두 앱의 차이는 권한 확인 하나로 유지된다. 코드에서 `checkPermission`을 읽는 자리가 권한 판단과 접속 기록 표시 두 군데뿐이어야 한다.
- 2번 앱을 "본보기"로 소개할 수 없다. 2번 앱도 학생 정보를 다른 곳으로 내보내는 앱이다.
- 전송은 권한 판단을 통과한 요청에서만 일어나므로, 2번 앱에서는 담임만 전송을 일으킬 수 있다. 이것은 전송의 차이가 아니라 권한 확인의 결과다.
- 받는 쪽은 두 앱이 보낸 것을 구분 없이 같은 목록에 쌓는다.
